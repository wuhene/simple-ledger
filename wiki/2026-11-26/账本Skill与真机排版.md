# 账本 Skill、双路检索与真机排版

需求分支 `2026-11-26` 基于已推送的 Android 0.2.3 验收分支。Web 与 Android 共用协议，账本仍在设备本地执行。

## 四层职责

| 层 | 入口与维护 |
|---|---|
| 视图 | Web 的 `assistant.js` 回复和卡片渲染、Android 的 `MainActivity.java`。进度来自实际的执行阶段，完成后的详情默认折叠并随会话保存。 |
| Agent | Web `assistant-model.js` 校验意图，`assistant-bridge.js` 拼接提示词并转给模型。Android `LedgerAssistant.java` 负责意图收敛、执行顺序、组织模型回复与本机回退。 |
| 业务逻辑 | `ledger-skills.js` 和 `LedgerSkills.java` 实现双路召回和通用排行，两端沿用现有日期汇总、比较、草稿和保存逻辑。 |
| 数据基础 | Web IndexedDB 和 Android SQLite 使用各自原有的同一词元倒排索引。索引原话、备注与开放线索，按流水 ID 去重，无需迁移数据。 |

共享 Skill 契约和例句位于 `project/shared/assets/ledger-skill-catalog.txt`。Web 本机服务启动时装载，Gradle 和 SDK 构建脚本都将同一目录加入 APK。添加 Skill 时更新契约、两端意图解析、业务实现和结果渲染，对照测试再发包。执行详情显示实际的步骤、匹配范围或笔数。调试时从步骤判断是模型意图、索引召回、本机计算或界面呈现的问题。

## 验收口径

- 搜索：程序提词、模型提词分别使用同一个索引，合并去重。城市线索为硬筛选，「北京烤鸭」的菜名不算作地点。只用分类和城市统计时读取完整匹配集。
- 排行：「我在北京吃饭最多的地方是哪」在预置账本应为王府井，2,000 笔。任意线索类型可作为维度，支持按笔数或金额排序。多人同餐每人可各计一次，同一人重复线索只记一次。缺失笔数单独显示。用餐时间按实际线索的小时或时段统计，入账小时使用设备时区解释 `createdAt`。
- 对比：两期沿用同一分类与线索筛选，使用本机笔数和金额。模型只接收匿名分组和有限的汇总事实，分组名称在本机替换。
- 记账：保留整句原话和开放线索，现有确认后保存的流程不变。定位坐标保留在本机，依然由明确的地名线索参加城市统计。
- 手机首页：明确设置正文与重点字重，金额使用等宽数字特性，减少流水标题上下留白并保留原有 58dp 流水触控行。继续尊重系统字号，厂商字体回退仍可能不同。

## 验证与接手

- Web 单元测试 12 项通过，覆盖双路取并集、硬筛选、线索覆盖率与去重。Chrome 导入验收包同一份 10 万笔样本，通过本地模型测试端点验证王府井 2,000 笔、两期对比及可展开执行步骤。
- Android 0.2.4（versionCode 8）的两个 APK 均通过 v2/v3 签名验证，独立验收包内有样本与共享 Skill 契约。Android 35 模拟器通过本地模型测试端点验证北京地点排行、匿名名称在本机还原、两期对比及展开真实执行步骤。
- 同一模拟器以默认和 1.15 倍系统字号检查首页，保留底部导航与流水触控尺寸。待截图来源真机复核系统字体、字重和行距，也待用户用已配置的模型试自然问法。合成数据缺少的实际消费线索会显示缺失笔数。
