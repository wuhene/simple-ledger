# 记账 App 产品需求文档

版本：1.1 · 2026-09-30 · 最终平台：原生 Android · 暂定名：简账

本版依据用户提供的 12 张鲨鱼记账截图重新设计。目标是保留截图中的日常记账和分析能力，以更简洁的界面实现。本文是开发规格；配套 UI 文档规定视觉和交互。开发流程按用户确认调整为：先在电脑浏览器用 HTML/CSS/JavaScript 验收样式和功能，确认后将页面、交互和业务逐项翻译、重写为原生 Android 代码并打包。Web 不要求与原生复用代码，不开发响应式产品布局。现有 HTML 原型只是起点，尚不满足完整功能验收要求。

## 1. 产品目标与边界

让用户快速记录一笔收入或支出，方便查看钱花在哪里、每月结余多少，并回顾长期账单。首页优先呈现当月金额与最近明细，避免账号推广、营销和社交内容占用记账空间。

默认单人使用、人民币、单账本、本地离线存储，无须登录。该实现方式是设计假设，不是截图能确认的原软件实现。暂不开发后端和云同步。金额不等于银行真实余额；结余不等于净资产。

## 3. 核心业务规则

### 3.1 记账

新增默认支出、业务日期为本地今天、分类为上次使用的同类型有效分类；首次支出选餐饮，首次收入选工资。金额清空、备注为空。切换收支后保留金额/日期/备注，只切分类到该类型的最近分类。

保存必须满足：金额大于 0、最多两位小数、不超过 99,999,999.99 元、分类有效、日期不晚于今天。最早日期为 1900-01-01，历史年份可记录。备注最多 200 个 Unicode 字符，前后空白裁剪；支持空备注。金额以整数“分”保存，禁止浮点累加。

键盘含数字、点、退格、加、减与保存。不支持乘除和括号。表达式从左到右按加减计算，例如 18.5+3-2=19.50。重复小数点忽略，连续运算符替换末尾运算符，结尾运算符时保存提示“请完成金额计算”；计算结果非正或超上限则留在当前页并提示。保存完成显示结果两位小数。

点击日期打开日期选择器。日期不同时，在确认键旁显示选定日期，避免补记误记为今天。备注输入调用系统键盘，关闭后恢复金额键盘，不同时显示两个键盘。

保存过程中禁用保存键，用同一草稿标识避免重复写入。成功关闭记账页，刷新所有受影响月份和统计，提示“已保存”；失败保留全部输入并允许重试。返回时：未改动直接退出；有改动弹出“放弃这笔记录？”按钮为“继续填写/放弃”。

编辑保留原记录 ID 和创建时间，更新修改时间。日期跨月时，同时更新原月与新月统计。详情页有独立删除按钮，确认后删除，提供 5 秒撤销；撤销恢复原记录及所有统计。删除后的空日分组消失。

### 3.2 分类

已确认支出默认分类：餐饮、购物、日用、交通、蔬菜、水果、零食、运动、娱乐、通讯、服饰、美容、住房、居家、孩子、长辈、社交、旅行、烟酒、数码、汽车、医疗、书籍、学习、宠物、礼金、礼物、办公，并补通用“其它”。截图末行裁切图标不列入已确认分类。

收入分类：工资、兼职、理财、礼金、其它、支付宝、微信。支付宝/微信是截图中已有的收入分类，迁移时保留，不默认要求用户使用。分类标签最长 8 个字符，同类型名称不可重复；同名跨类型允许。每个类型至少保留一个有效分类。

分类管理可选择内置线性图标、拖动排序、隐藏/恢复。历史引用的分类不可物理删除；隐藏后仍出现在历史记录和统计中，新增记账不显示，编辑该历史记录可保留原分类或改选。改名影响历史展示，分类 ID 不变。没有引用的自建分类可确认后删除。

### 3.3 明细

页面范围是选定自然月。按业务日期降序分组，同日按创建时间降序，ID 作为稳定的次级排序。每天展示日期、当天收入/支出；每行显示分类图标、名称、备注（最多一行省略）、金额。收入带“+”，支出带“−”。无备注时不占第二行。

月收入、月支出均显示正数，结余=收入−支出，可以为负。首页“结余”不叫“余额”。点击月份弹出年月选择；左右切换快捷手势不作为唯一操作，提供前后月按钮。历史月份允许空数据，未来月份只读查看空账单，不允许新增未来日期。

首次空状态“还没有记录，记下第一笔吧”；历史空月“这个月暂无记录”。两者均保留记账入口。加载失败显示重试，不拿 0 替代失败值。

### 3.4 统计口径

| 指标 | 计算规则 |
|---|---|
| 收入 I / 支出 E | 范围内对应类型金额之和，不含已删除记录 |
| 结余 S | I−E；为收支流量差，不是净资产 |
| 周范围 | 周一至周日，按本地日期；当前周截至今天 |
| 月范围 | 该自然月；当前月截至今天 |
| 年范围 | 该自然年；当前年截至今天 |
| 日均 | 所选类型总额÷统计经过的日历天数；历史完整周期用完整天数，无记录日也计入 |
| 单日最高 | 各业务日该类型金额总和的最大值；并列选最早日期，可展开列出并列 |
| 单笔最高/排行 | 按单笔金额降序，金额同值按业务日期降序 |
| 分类占比 | 分类合计÷该类型总额；总额为 0 时不计算百分比 |
| 环比差额 | 当前自然月合计−上个自然月合计；本月未结束标“本月至今对比上月全月” |
| 环比比例 | 上月>0 时差额÷上月；上月=0 显示“上月无记录”，不显示无穷大 |

月报告的单日最高不能用单笔最高替代。截图 9 月日均 250.47=7,514.17÷30；本版规则为“截至今天”，在 9 月 30 日与截图一致，9 月 15 日使用 15 天作分母。

周/月趋势按天；年趋势按月。无数据但已经过的日期补 0；未来日期为无数据区域，不画成支出为 0 的实际数据。折线横轴降低标签密度，点击点显示完整日期和金额。统计页排行列出全部分类，默认按金额降序。

### 3.5 账单与报告

月账单模式选择年份，汇总该年截至当前的收入/支出/结余，显示该年有记录或有预算的月份；可展开“全部月份”查看空月。年账单模式顶部显示所有记录年份的总收入/总支出/总结余，各年倒序。历史不固定为截图的 2018—2026 年。

月报告内容按序：本月收支/结余与上月结余 → 支出组成与分类表 → 支出单笔前 5 名（可看全部） → 单日最高/日均/日趋势 → 最近 6 个月支出对比 → 变化最大的 3 个分类 → 收入组成 → 最近 6 个月收入对比 → 当前成就 → 分享。

支出组成圆环最多 5 个分类，其余合并“其它分类”；原本名为“其它”的分类仍是独立分类，合并组另用名称，完整表不合并。类别变化按差额绝对值降序取前三，保留增加/减少文字与金额；不只取增加，也不把增加支出描述成好成绩。上月没用而本月新增的分类标“新增支出”。同值按分类排序序号。

最近 6 个月包含报告月，缺失月份填 0，跨年标签用“25年12月”；报告未来月时显示暂无报告。单笔排行下钻到记录详情。年报告采用年收支/结余、12 个月收支趋势、全年分类占比和排行，不杜撰年度成就奖章。

分享生成报告图片，Web 验收阶段提供图片预览与下载，原生 Android 阶段调用系统分享面板；不开发微信/QQ专属按钮或独立社交登录。默认只含汇总图表，不含备注/单笔排行/资产/个人姓名；确认页可开关“包含排行”和“包含成就”，预览后再分享。生成失败提示重试，取消分享不影响记录。

### 3.6 月总预算

预算按年月独立保存，无预算显示“设置本月预算”，而不是剩余 0%。设置金额范围 0.01—99,999,999.99。已用=该月支出；剩余=预算−支出。使用比例=支出÷预算；进度条显示值限制 0—100%，文字可以显示 120%。超支时显示“已超支 ¥…”，不显示负数“剩余”。收入不增加预算。

新月份默认无预算，不自动继承。历史预算允许修改，需清楚显示所选年月。修改不改任何流水。删除预算需确认；当月及历史支出仍保留。

### 3.7 资产概览（最小假设）

截图仅确认资产、负债、净资产三个数。本版使用手动维护的两个非负汇总金额：资产总额、负债总额；净资产=资产−负债。允许为负净资产。首次显示“尚未设置”，不能把未知值当作 0；两个金额明确填 0 时才展示 0。

修改总额附更新时间，不生成收入/支出记录，不与记账自动联动。页面说明：“资产为手动维护，收支记录不会自动改变资产。”不扩展银行卡/信用卡/债务明细/转账。

### 3.8 记账成就

记账总天数=至少有一笔有效记录的不同业务日期数量；总笔数=有效记录数；连续记账天数=从今天回溯的连续有记录业务日期数，今天无记录时从昨天开始计算，昨天也无记录则为 0。补记参与历史连续性计算；同日多笔只加一天；删除当日最后一笔会重算。它是记录日期连续性，不是启动 App 打卡；“记账成就”无需单独打卡按钮。

## 4. 数据结构与本地存储

最终采用原生 Android UI 和本地数据库；默认实现建议为 Java + Android XML/View + Room（SQLite），工程初始化时固定兼容的依赖与工具链。Web 阶段可采用 HTML/CSS/JavaScript 与 IndexedDB 本地存储以支持功能验收，但不把这些技术带入原生生产界面。正式 APK 不以 WebView、Capacitor 或其它网页容器承载核心页面。Web 和原生分别实现业务、存储与界面，以同一份 PRD、数据模型和验收样例保证一致。

| 实体 | 关键字段 | 约束 |
|---|---|---|
| Entry | id、type、amountMinor、categoryId、businessDate、note、createdAt、updatedAt | type=EXPENSE/INCOME；金额整数分；日期 YYYY-MM-DD；ID 唯一 |
| Category | id、type、name、iconKey、sortIndex、hidden、isBuiltin | 同类型有效名称唯一；历史引用保留 |
| MonthlyBudget | yearMonth、amountMinor、updatedAt | yearMonth 唯一 |
| AssetSnapshot | id=单例、assetMinor、liabilityMinor、updatedAt | 未设置状态可为空；负债和资产均非负 |
| Preferences | hideAmountsByDefault、schemaVersion | 全局显隐仅改变展示 |

Entry 写入和对应变更必须以数据库事务完成。统计可现场聚合，若缓存则编辑/删除后按受影响日期范围失效，绝不能只刷新首页。业务日期保持用户选择的日历日，改变设备时区不把历史记录挪到另一天；创建/修改时间为时间戳。

备份文件是带 schemaVersion 的 JSON，包含流水、分类、预算、资产及设置，Web 阶段通过浏览器下载导出、文件选择恢复；Android 阶段使用系统文件选择/保存。最终App不申请读取联系人或短信权限。恢复前校验版本、结构、ID、金额、日期、分类引用及记录数量，展示恢复预览和“将替换当前全部数据”的提示。恢复为全量替换，先在事务内建立回滚保障，校验失败不改数据；取消不改数据。不做本版合并导入。恢复前生成备份：Web阶段成功触发下载后需用户确认已保留备份，因为浏览器不能仅凭下载事件确认磁盘写入；原生阶段按文件保存结果确认成功。备份未确认时停止恢复。清空数据双重确认，并提供先导出选项。

旧软件历史导入暂不实现：截图不能提供可导入格式，需要后续取得实际导出样本才能定义迁移。用户的旧数据不会因原型里的示例数字自动被导入。

## 5. 主要流程与状态

| 场景 | 流程 | 完成结果 |
|---|---|---|
| 记支出 | 首页新增 → 分类 → 金额 → 可选备注/日期 → 保存 | 返回来源页；汇总和明细立即更新 |
| 记收入 | 新增 → 收入 → 工资等分类 → 金额 → 保存 | 收入和结余更新；支出预算不变 |
| 补记 | 新增 → 日期 → 过去日期 → 保存 | 归入历史日/月，不强行跳到该月；成功提示日期 |
| 修改 | 明细 → 详情 → 编辑 → 保存 | 原记录覆盖；跨月重算两月 |
| 删除 | 详情 → 删除确认 → 删除 → 可撤销 | 无记录月份汇总为 0；成就同步重算 |
| 查看分类 | 统计排行 → 分类明细 → 单笔详情 | 继承收支类型和完整周期 |
| 月账单 | 工具 → 账单 → 选年 → 选月 | 报告明确所选年月；返回保留滚动位置 |
| 预算 | 工具 → 预算 → 输入 → 保存 | 已用不变，剩余重算 |
| 恢复失败 | 选文件 → 校验失败 | 显示具体错误，原数据不变 |

状态必须覆盖：首次空、历史空、正常、计算中、保存中、失败重试、未设置预算、预算超支、资产未设置、全局隐藏金额、分类隐藏、未完成输入退出。

## 7. 非功能验收与交付说明

参考数据规模为 10 年、10 万笔。性能目标（待开发阶段实际验证）：冷启动目标 2 秒内可操作、常用月列表/统计目标 300ms 内响应、分页明细滚动不阻塞输入；重统计与备份在后台执行，失败可恢复。

所有本版核心记账能力离线可用。字号随系统设置缩放；按钮触控区至少48dp；收入/支出、超支与增减不只依靠颜色。系统返回键和返回手势按页面层级退回，未保存草稿先确认。金额隐藏同时影响首页、统计、报告和资产，不是单独遮住一个数字。

当前设计交付物：本 PRD、UI/UX 设计文档、可点击 HTML 原型。现有原型以 2026 年9月截图数据作视觉参考，页面里的最近明细、预算设置值与资产填写例子为演示数据，不是已完成的功能版。后续Web验收版需实现真实数据联动与可验证的功能；原生阶段再逐项重写并生成APK，按同一验收清单复验。

配套UI文档1.0中的页面和Android视觉规范继续适用；其对“现有原型是演示”的说明不代表后续Web功能验收可用模拟按钮代替实现。若旧文档/原型存在电脑响应式布局示例，不构成当前需求，以本PRD的固定手机画布和原生实现路线为准。

仍需后续确认的实现输入：旧软件可用导出格式、是否需要云同步、是否扩展多账本/资产账户明细。这些不阻塞当前限定范围设计，也不默认进入本版。

## 8. 实施路线：Web验收 → 翻译为原生 → APK

### 8.1 用户确认的开发方式

先用Web在电脑上验收样式和功能，发现问题及时修改。Web通过验收后，将已经确认的页面布局、导航、组件交互、计算逻辑和数据读写逐项翻译、重写为Java/Kotlin原生Android代码，随后测试与打包。

不要求Web和Android共用代码，不采用网页封装，也不做桌面/手机响应式Web产品。Web承担正式的前期验收作用，而不仅是展示静态图片。最终应用采用原生UI与本地数据库。

“翻译”为开发者按已验收行为重新实现原生代码：页面对应原生布局/组件，交互对应事件与导航，业务对应原生业务层，存储对应SQLite。完成每个模块后用同一测试数据复验，确保原生行为和Web验收结果一致。性能目标以原生真机测量为准。

### 8.2 分阶段交付与验收门槛

| 阶段 | 工作 | 交付/通过条件 |
|---|---|---|
| S0 现有设计参考 | PRD、UI文档、可点击HTML样机 | 确定初始方向，明确现有快照与演示数据 |
| S1 Web功能验收版 | HTML/CSS/JavaScript；固定手机画布；实现第1—6节可在浏览器执行的功能 | 电脑可打开或本地启动；能够连续操作真实记账流程，存储与统计联动；提供源码与启动说明 |
| S2 调整与验收冻结 | 根据用户反馈改样式、功能、文案和状态 | 页面/流程验收通过；第6节业务用例通过；记录已确认设计及仅Android可验证的待办 |
| S3 原生翻译实现 | 按验收版逐页、逐模块重写为原生Android；实现数据库与平台能力 | 可安装调试；相同数据得到相同结果；逐项功能对照通过 |
| S4 原生调试与打包 | 真实手机验证、性能优化、修复平台差异、生成APK | 完整原生源码、构建说明、可安装测试APK；需要发布时再生成签名包，不自动上架 |

### 8.3 Web样式验收：固定手机画布

- 主验收画布为390×844 CSS px；电脑窗口更大时只居中显示，不变为桌面产品布局。
- 可手动切换360px/390px两个手机参考宽度检查设计；不开发响应式侧栏、多列桌面布局或桌面专属功能。
- 原型页面目录可作为电脑评审工具，但不出现在正式App。
- 保持四个主导航、记账入口、P01—P14页面；颜色、字号、间距和组件按UI文档。
- 支持鼠标点击、滚动及键盘填写，便于电脑验收；手机画布内也须能够完成全部基本流程。
- 页面涉及未设置、空数据、超支、错误、隐藏金额、删除确认和未保存退出时，需有可查看/触发的状态，不只展示正常状态。

最终原生App仍需适配手机屏幕、系统字体和安全区；不做响应式Web并不意味着原生界面可以裁切或只能支持一个物理分辨率。

### 8.4 Web功能验收：真实联动，不用静态快照代替

Web验收版必须支持新增、编辑、删除与撤销、切换日期/分类、周月年统计、月年账单、预算、资产、分类管理、成就与备份恢复。流水修改后首页、统计、报告、预算和成就都应正确更新；不得继续固定显示截图金额。

浏览器账本采用IndexedDB保存，刷新及正常重开后保留记录。页面业务逻辑和数据库读写分层组织，便于阅读与原生翻译，不要求和原生共用实现。localStorage不作为正式验收流水数据库。浏览器数据属于当前浏览器与当前origin，改变主机、端口或浏览器后不保证自动出现，因此提供真实可用的JSON备份导出/恢复。

正式开发预览建议使用固定地址的本地HTTP服务器，便于开发者工具调试和数据持久化；单文件HTML可用于样式评审，不强求把完整工程打成一个HTML文件。

仅原生能力在Web阶段允许使用明确替代流程：

| 功能 | Web验收方式 | 原生实现方式 |
|---|---|---|
| 记账与统计 | 实际浏览器数据、计算和联动 | 原生业务层及数据库，复验相同结果 |
| 日期/备注/返回 | 浏览器控件、输入及页内返回 | 原生日期控件、系统键盘与返回键/手势 |
| 账本持久化 | IndexedDB，刷新重开验证 | Room/SQLite，杀进程重开及升级验证 |
| 备份恢复 | JSON下载、选文件校验并恢复 | Android系统文件选择/保存与事务恢复 |
| 报告分享 | 实际生成图片预览/下载 | 图片生成后调用Android系统分享 |
| 手机性能/系统适配 | 不作为Web已通过项目 | 模拟器与真机专项验证 |

本地服务器开发预览不等于离线PWA；本版不要求Web安装或发布网站。最终Android包不依赖电脑服务器或线上页面，断网可运行核心功能。

Web验收数据默认是测试数据，不自动进入手机账本。若需保留用户真实数据，通过同schemaVersion的JSON导出/原生恢复迁移，核对ID、笔数、业务日期、分类、预算、资产和收支合计；不承诺电脑与手机自动同步。

### 8.5 原生翻译要求与对照清单

默认建议Java + XML/View原生组件 + Room（SQLite），结合用户Java开发背景实施；若工程选择Kotlin，应保持全部业务行为一致。初始化时核对并固定最低Android版本、JDK/SDK/Gradle与依赖兼容版本，不直接套用旧JDK8环境。

| Web已验收内容 | 原生交付要求 |
|---|---|
| 页面与样式 | 原生布局和组件按同一UI规范重建，不嵌入HTML充当生产页面 |
| 导航与弹层 | 原生页面导航、弹窗、返回手势和草稿确认保持一致 |
| 金额/日期/校验 | 翻译为Java/Kotlin业务规则；金额仍为整数分，业务日期不因时区变化挪动 |
| 明细与图表 | 原生列表和图表；长列表分页/分段加载；数字与查询口径一致 |
| 数据写入/统计 | 原生Repository与数据库事务；查询/重统计不阻塞主线程 |
| 数据格式 | JSON字段与schemaVersion兼容；数据库升级需迁移与失败恢复保障 |
| 反馈与异常 | 空态、失败、保存中、超支、分类隐藏和撤销都有原生实现 |

每完成一个模块，就用Web通过的同一份测试数据核对结果，再整体验证；原生不只是“长得一样”，操作与业务结果也要一致。
