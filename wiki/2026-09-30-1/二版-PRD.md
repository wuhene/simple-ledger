# 简账二版 · 体验优化 PRD

版本：2.0 设计稿 · 2026-09-30 · 分支：`2026-09-30-1` · 状态：待验收

## 1. 背景与目标

初版 Web 已具备日常记账、明细、统计、预算、账单、资产、分类及本地数据管理。用户反馈“有点过于简洁”“跟原始无样式差不多”，尤其希望日历选择、按钮和切换、记账过程更精致。本需求先完成 PRD 与 UI 视觉方案，用户确认后再实现。

二版目标：在保持初版操作路径和业务规则的前提下，让主操作更容易识别，选日期与记一笔更顺畅，页面切换有明确的空间关系与完成反馈。设计基调是有温度的轻量工具，避免过多卡片、颜色和持续动画干扰账目阅读。

### 1.1 范围

| 优先级 | 范围 | 交付定义 |
|---|---|---|
| P0 | 日期选择 | 首页选年月、记账选日使用一套视觉语言；快速选择、禁用未来日期、确认/取消、键盘输入回退 |
| P0 | 按钮体系 | 主要、次要、文字、危险、悬浮按钮及禁用/加载/按下状态 |
| P0 | 记账流程 | 收支切换、分类选择、金额键盘、日期/备注、保存反馈的布局与动效 |
| P1 | 页面切换 | 底部导航、明细与详情、弹层、月份/统计周期切换的转场规则 |
| P1 | 视觉层级 | 首页月概览、记录列表、导航栏、统计页的颜色、字级、圆角和图标统一 |
| P1 | 无障碍 | 降低动态效果、大字、触控范围、读屏文案、焦点与错误提示 |

本需求不新增账务字段、算法、账户、云同步、支付读取或后端；初版 PRD 中金额校验、草稿、撤销、统计口径、备份恢复等规则继续生效。本轮仅交付设计文档和静态视觉稿，不修改 `project/`。后续 Web 实现、用户验收、原生 Android 重写与 APK 各自按项目协作约定推进。

## 2. 关键使用路径

### 2.1 首页查账与切月

1. 启动进入明细首页，标题区提供“2026 年 9 月”年月按钮，旁边有上一月、下一月按钮。下一月允许浏览未来空账单；选日期用于记账时则禁止未来日期，两种语境清楚区分。
2. 点击年月按钮打开“选择月份”弹层，顶部年份切换，主体为 12 个月网格，当前选中月份有实心色块与可读标签；点击月份立即预览待选择值，按“查看此月”提交，按取消或系统返回保留原月。
3. 相邻月快捷切换时，标题和数据朝方向轻移；加载中维持旧数据并显示局部进度，成功后替换。空月显示“这个月暂无记录”和“记一笔”。
4. 月概览突出结余，收入、支出作为同一张概览中的次级信息。记录按日期分组，金额仍为阅读主角。

### 2.2 新增一笔

1. 任一主导航页点击“＋ 记一笔”进入记账页。入口扩展到新页面，页面标题明确“记一笔”。默认支出、今天、最近有效分类，金额为空，遵循初版 PRD。
2. 收支分段切换后，选中块平移、分类内容淡化再出现，保留已输入金额、日期和备注。选择分类时对应图标容器短暂放大后回到原尺寸，同时更新金额区的分类标签。
3. 金额键盘按键有即时压下反馈；加减表达式、两位小数、最大值等逻辑沿用初版。金额过长缩小字级并允许横向查看，不能遮挡保存按钮。
4. 日期行展示完整“年-月-日”和星期；非今天时附“补记”提示。备注行可输入文字。打开系统输入法时自定义金额键盘隐藏。
5. 保存键只有一个明确主动作。无效金额在金额区显示具体错误，保存键可点击并引导定位；保存中禁用重复触发并显示“保存中…”。成功后返回来源页、刷新数据并短暂提示“已记下”；失败保留草稿和错误原因。
6. 编辑、退出草稿、删除与撤销规则延续初版 PRD。关闭有改动的草稿前仍需确认。

### 2.3 记账日期选择

1. 日期行打开底部日历弹层。顶栏显示当前预选的完整日期，默认聚焦记录日期；新增默认今天，编辑默认原日期。
2. “今天”“昨天”作为快捷按钮。月标题左右切换。星期一为每周第一列；当月日期为主色，邻月日期弱化且不可点击；今天有描边圆圈，选中日期为实心圆，两个状态重叠时以选中态为主并用小点提示今天。
3. 超出 1900-01-01 至今天范围的日期不可选。月份快速跳转可打开年/月选择；另提供“输入日期”模式，格式 `YYYY-MM-DD`，允许手动输入历史日期，验证合法性和闰年。
4. 点击日期只更新预选值；按“确定”才写回记账表单，按“取消”、关闭按钮或系统返回均不更改原值。日期与金额、分类等草稿独立保存，不因关闭日历丢失。
5. 1900 年边界、跨年翻月、闰年 2 月、不同月份首日对齐、未来日期禁用、输入无效日期、键盘遮挡均有对应设计状态。

### 2.4 页面与周期切换

| 场景 | 交互要求 |
|---|---|
| 底部四导航切换 | 选中图标、标签与柔和底色同步变化；内容淡出淡入；返回该页保留最近周期和滚动位置 |
| 首页/统计切月份或周、年 | 数字更新前保持旧值可读，过渡结束后呈现新值；快速连续点击以最终目标周期为准 |
| 记录行进入详情 | 行与详情金额之间建立视觉连续性；系统返回回到原滚动位置 |
| 弹层打开/关闭 | 背景轻度变暗，弹层从底部进入；关闭手势、取消和系统返回行为一致 |
| 错误或网络无关的本地保存失败 | 不播放成功转场，留在表单并呈现可操作错误 |

## 3. 组件行为与状态

| 组件 | 默认 | 按下/选中 | 禁用/加载 | 错误/空态 |
|---|---|---|---|---|
| 主要按钮 | 高对比实心，动作动词可见 | 小幅缩放与颜色加深 | 低对比且不可操作；加载文字保留宽度 | 错误关联具体输入区，不仅靠 Toast |
| 次要按钮 | 浅色容器或描边 | 清晰按下反馈 | 文本仍可读 | 不与危险动作混用 |
| 悬浮记账按钮 | 图标＋文字；避开底部导航 | 入口到记账页连贯过渡 | 正在保存时不重复打开 | 空态也保持可发现 |
| 日期单元格 | 日期文字 | 选中圆与读屏“已选中” | 未来日期不响应；视觉变淡 | 非法输入给出原因和允许范围 |
| 分类单元格 | 图标＋名称 | 选中背景＋标记，非仅改色 | 隐藏分类不出现在新增页 | 无分类时给“管理分类”入口 |
| 金额键盘 | 对齐、足够间距 | 压下反馈≤120ms | 备注输入时隐藏 | 表达式错误在金额区内联 |

## 4. 动效与性能原则

动效只解释操作结果：页面进入、容器展开、选择状态、保存成功。持续循环、装饰性弹跳和金额逐位滚动均不采用。详细时长与曲线见《二版-UI设计文档》。以 60fps 为目标，动画期间不阻塞触控；低性能设备可以直接完成状态切换。系统启用“减少动态效果”时，取消位移、缩放和容器变形，保留极短淡入及必要状态变化。

## 5. 验收标准

### 设计验收（本分支）

- PRD、UI 规范和视觉稿覆盖首页、日历、记账三个主要画面，以及按钮、导航和动效的状态。
- 图中每个可交互控件在文档中有默认、选中、禁用/加载及必要错误行为，且与初版业务规则无冲突。
- 能按文档从首页复述“查指定月”和“补记一笔”的完整操作，包括取消、失败、返回与减少动态效果。
- 日期选择明确区分首页月份浏览与记账日期校验；保存前能看出是否为补记。
- 视觉稿可读、层级明确，记录金额与保存动作比装饰元素更醒目。视觉稿示意数据不代表真实账本。

### 后续实现验收（设计批准后）

- 在 390×844 Web 画布和 360px 宽度下，首页、日期弹层、记账页没有横向溢出或遮挡核心操作。
- 触控区至少 48×48 CSS px / 原生 dp；200% 字体放大时可滚动访问保存键。
- 快速切换月份或标签，最终显示目标周期数据；不会把旧月份数字短暂标成新月份。
- 日历取消不会改日期；选未来日期不可提交；手输非法日期有内联说明。
- 保存按钮加载时只提交一次，成功和失败反馈与实际持久化结果一致。
- `prefers-reduced-motion` / Android 减少动态效果启用时，无明显位移与缩放动画。
